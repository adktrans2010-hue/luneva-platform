# Luneva Platform — production readiness report

Дата этапа: 2026-07-24

## 1. Что проверено

- Проект использует Next.js App Router: страницы находятся в `app/`.
- Middleware-слой реализован через `proxy.ts`.
- Серверные редиректы настроены в `next.config.ts` и `proxy.ts`.
- `robots.txt` формируется через `app/robots.ts`.
- `sitemap.xml` формируется через `app/sitemap.ts`.
- 404-страница существует в `app/not-found.tsx`.
- Публичные маршруты, legacy-редиректы и SEO-базовые признаки проверены локальным production smoke-тестом.
- Запись на консультацию проверена по коду: публичная покупка использует только `isPublic=true`, создание записи защищено транзакцией и advisory lock.
- Доступ к серверу для дополнительной проверки БД/PM2 не выполнен: SSH вернул `Permission denied`.

## 2. Найденные проблемы

- Legacy URL `/?page_id=812` обрабатывался слишком узко: редирект вел на `/blog`, но терял остальные query-параметры. Для рекламного трафика это могло приводить к потере UTM-меток.
- В рабочем дереве есть много untracked служебных файлов: архивы, дампы, audit-результаты, rollback artifacts. Их нельзя добавлять в Git без отдельного решения.
- Серверная проверка production-БД и текущего PM2-состояния не выполнена из-за недоступного SSH-доступа.

## 3. Что исправлено

- В `proxy.ts` добавлен отдельный обработчик legacy WordPress query:
  - `/?page_id=812` теперь возвращает постоянный серверный редирект на `/blog`.
  - Параметр `page_id` удаляется.
  - Остальные query-параметры, включая UTM, сохраняются.
- Существующая логика защиты `/admin`, `/account` и CSRF в `proxy.ts` сохранена.

## 5. SEO и индексация

- `robots.txt` запрещает индексацию технических и приватных зон: `/admin`, `/api`, `/account`, `/profile`, `/login`, `/register`, восстановление пароля и verification.
- `sitemap.xml` собирает публичные страницы, опубликованные статьи, раздел РПП, тематические help-страницы и юридические страницы.
- Legacy WordPress URL в sitemap не добавляются.
- Для `/help/eating-disorders` уже выбран канонический смысловой маршрут `/rpp`.

## 6. Запись, оплата и тестовые услуги

По коду подтверждено:

- Публичная форма получает продукты через `getPublicConsultationProducts()`, где отбираются только `isActive=true`, `isPublic=true`, без `archivedAt`.
- Создание записи использует `findPurchasableProduct(... publicPurchase: true)`, то есть непубличные услуги не должны покупаться с сайта.
- Перед созданием записи проверяется выбранный свободный слот.
- При создании записи используется транзакция и `pg_advisory_xact_lock` по ключу формата, локации и времени.
- Оплата создается после резервирования слота; при ошибке оплаты запись переводится в `expired/failed`.

Не выполнено:

- Не проверен фактический production-продукт "Тест сессия" в БД, потому что SSH-доступ к серверу вернул `Permission denied`.
