# Приёмка меню и раздела «Энциклопедия РПП»

Дата проверки: 22.07.2026  
Итоговый статус: **YELLOW — технических блокеров нет, нужны решения владельца и экспертная проверка отдельных материалов.**

## 1. Исходное состояние перед этапом

- Новое desktop/mobile-меню, RPP-раздел, заглушки раздела помощи, категории блога, хлебные крошки, sitemap и редирект `/about/education` уже существовали.
- Статусы публикации были распределены между конфигурацией навигации и описаниями RPP-страниц.
- Заглушки разделов «Помощь» и RPP отображались в публичном меню как готовые материалы.
- Все семь категорий блога отображались в меню независимо от наличия опубликованных статей.
- Сопоставление категорий статей допускало неточный поиск по части строки.
- Не было полного регрессионного покрытия настоящих 404, фильтрации меню, `noindex`, sitemap и адаптивных состояний.
- Рабочая директория до этапа уже содержала значительное количество несвязанных локальных изменений. Они не отменялись и не включались в рефакторинг этого этапа.

## 2. Найденные проблемы

1. В публичной навигации рекламировались страницы со статусом заглушки.
2. После скрытия всех дочерних страниц у пункта «Помощь» могла остаться пустая логика раскрытия.
3. Пустые категории блога показывались посетителям и могли попасть в sitemap.
4. Категории статей сопоставлялись недостаточно строго, что создавало риск ошибочного назначения материалов.
5. Структурированные данные могли формироваться для технических заглушек и пустых категорий.
6. Статусы RPP дублировались отдельным булевым полем вместо единого типизированного механизма.
7. Не хватало автоматических проверок неизвестных вложенных URL, мобильного меню, активных состояний и горизонтального переполнения.

## 3. Что исправлено

- Создан единый типизированный реестр `published | draft | placeholder` в `src/lib/publication-status.ts`.
- Публичная навигация автоматически фильтруется по этому реестру; пустые группы и CTA не выводятся.
- «Помощь» стала прямой ссылкой на `/help` без стрелки и пустого подменю.
- Девять help-заглушек и три RPP-заглушки скрыты из desktop/mobile-меню и внутренних автоматических списков.
- В меню статей оставлена только непустая утверждённая категория `/blog/category/crisis-self-help`.
- Для категорий включено точное нормализованное сопоставление без догадок и поиска по подстроке.
- Пустые категории получают `noindex, nofollow`, не формируют structured data и исключены из sitemap.
- RPP-страницы используют единый статус; structured data формируется только для опубликованных страниц.
- Sitemap включает только опубликованные RPP-материалы и реально непустые утверждённые категории.
- Добавлено и обновлено регрессионное Playwright-покрытие меню, 404, SEO, sitemap и адаптивности.

## 4. Обработка неизвестных URL

- Общий `app/[...slug]/page.tsx` обслуживает только опубликованную страницу из базы либо точное совпадение с белым списком `placeholderPages`.
- Любой неизвестный slug завершает обработку через `notFound()` и возвращает настоящий HTTP 404.
- `app/rpp/[[...slug]]/page.tsx` принимает только slug из типизированной карты RPP; неизвестные и лишние вложенные сегменты возвращают 404.
- `app/blog/category/[category]/page.tsx` принимает только семь утверждённых slug категорий; неизвестная категория возвращает 404.
- Системные и служебные маршруты catch-all не перехватывает.
