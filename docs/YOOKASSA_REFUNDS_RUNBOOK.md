# ЮKassa: возвраты и отмены

## Текущий режим платежей
Сайт создает платежи ЮKassa в одностадийном режиме:

```text
capture: true
```

Обычный путь платежа:

```text
created locally -> pending/invoice_sent -> succeeded/paid или canceled/cancelled
```

`waiting_for_capture` поддержан для синхронизации и отмены авторизации, но сайт специально не включает двухстадийную схему.

## Как выполнить полный возврат
1. Откройте админку, раздел "Записи".
2. Найдите оплаченную запись.
3. В блоке "Финансы ЮKassa" проверьте статус и доступный остаток.
4. Нажмите "Вернуть всю сумму".
5. Укажите причину.
6. Введите подтверждение `ВОЗВРАТ`.
7. Сайт создаст локальную попытку возврата, выполнит реальный запрос `POST /v3/refunds`, затем синхронизирует статус через API ЮKassa.

Финансовое действие доступно только при действующей админской сессии. Без входа в админку API вернет 401/403 и не создаст возврат.

## Как выполнить частичный возврат
1. В карточке записи нажмите "Вернуть часть суммы".
2. Укажите причину.
3. Введите сумму в рублях.
4. Сервер проверит, что сумма больше нуля и не превышает доступный остаток.

Если ЮKassa отклонит частичный возврат для конкретного способа оплаты, сайт сохранит ошибку и не отметит платеж как возвращенный.

## Как отменить waiting_for_capture
Если платеж находится в статусе `waiting_for_capture`, в карточке появится действие "Отменить авторизацию".

Сайт выполнит:

```text
POST /v3/payments/{payment_id}/cancel
```

## Как проверить результат
Проверьте статус платежа, сумму "Возвращено", сумму "Доступно", историю записи, уведомление владельцу и уведомление клиента в кабинете.

Для ручной проверки:

```powershell
npm run payments:reconcile -- --dry-run
npm run refunds:reconcile -- --dry-run
```

`--dry-run` ничего не меняет в базе.

## Как обработать неуспешный возврат
Если возврат завершился `canceled`, сайт сохраняет `cancellationParty`, `cancellationReason`, `errorCode`, событие в истории и событие в `payment_events`.

Платеж не переводится в `refunded`. После устранения причины можно создать новую попытку возврата.

## Возврат из кабинета ЮKassa
Если возврат создан вручную в кабинете ЮKassa, сайт узнает о нем через webhook `refund.succeeded`.

Процесс:

1. Webhook получает только ID возврата.
2. Сайт запрашивает актуальный возврат через `GET /v3/refunds/{refund_id}`.
3. Находит локальный платеж по `payment_id`.
4. Создает локальный `yookassa_refunds` с `requestedBy = yookassa_dashboard`.
5. Обновляет сумму возврата и статус платежа.
6. Добавляет историю и уведомляет владельца.

Если платеж не найден, создается событие `manual_review`.

## Как вручную восстановить синхронизацию
Если у возврата есть `providerRefundId`, вызовите:

```text
POST /api/admin/refunds/{id}/sync
```

Для массовой сверки:

```powershell
npm run refunds:reconcile -- --dry-run
npm run refunds:reconcile
```

## Какие webhook включить
В кабинете ЮKassa нужно вручную включить события:

```text
payment.waiting_for_capture
payment.succeeded
payment.canceled
refund.succeeded
```

Webhook URL:

```text
https://luneva-psy.ru/api/yookassa/webhook
```

Сам факт наличия маршрута в коде не означает, что webhook включен в кабинете.

## Как протестировать в тестовом магазине
1. Включите тестовый магазин ЮKassa или тестовый режим.
2. Укажите тестовые `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY`.
3. Создайте тестовую запись и оплату.
4. Проверьте `payment.succeeded`.
5. Выполните частичный возврат.
6. Выполните полный возврат остатка.
7. Проверьте webhook `refund.succeeded`.
8. Запустите dry-run сверку.

Боевые платежи и возвраты для тестов использовать нельзя.

## Чеки при возвратах
В коде есть техническая структура для статуса чека возврата, но налоговые параметры `receipt` не добавлены, потому что в проекте не подтверждены `vat_code`, `payment_mode`, `payment_subject` и правила возврата пакетов консультаций.

Перед боевыми возвратами нужно подтвердить фискальную схему в ЮKassa и у бухгалтера/налогового специалиста.

## Перед вводом в эксплуатацию
1. Сделать резервную копию production PostgreSQL вне Git-каталога.
2. Проверить production-базу на дубли `providerPaymentId`, `idempotenceKey`, `yookassaPaymentId` и неизвестные `paymentStatus`.
3. Применить миграции `0028_yookassa_payment_attempts.sql` и `0029_yookassa_refunds.sql`.
4. Проверить, что `YOOKASSA_RETURN_URL` и `NEXT_PUBLIC_SITE_URL` указывают на `https://luneva-psy.ru`.
5. В кабинете ЮKassa включить `refund.succeeded`; наличие маршрута в коде не включает событие автоматически.
6. Запустить на сервере:

```powershell
npm run payments:reconcile -- --dry-run
npm run refunds:reconcile -- --dry-run
```

7. Не выполнять реальные платежи и возвраты, пока не подтверждены чеки/receipt.

## Запрещено
- Менять `payment_status` на `refunded` напрямую в базе.
- Делать возврат без API ЮKassa.
- Выполнять автоматический возврат только из-за отмены записи.
- Удалять финансовую историю.
- Логировать `Authorization`, Secret Key, данные карты или CVC.
- Возвращать больше доступного остатка.
- Тестировать на боевых финансовых операциях.
