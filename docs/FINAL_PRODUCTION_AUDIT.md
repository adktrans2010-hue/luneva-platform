# Финальный production-аудит Luneva Platform

Дата проверки: 2026-07-19  
Область проверки: локальная рабочая копия проекта перед production, модерацией ЮKassa и запуском рекламы.  
Ограничения: commit, push, deploy, production migration, реальные платежи, реальные возвраты и изменение production env не выполнялись.

## Итоговый вердикт

Production запускать сейчас нельзя.

Сайт технически собирается, TypeScript и lint проходят, но текущий код уже зависит от новой таблицы `consultation_products`. В локальной базе эта таблица отсутствует, поэтому production-сервер падает на главной странице при smoke test. Это означает, что код и база данных сейчас не синхронизированы.

На модерацию ЮKassa отправлять пока нельзя. Основные причины: нет отдельной страницы `/payment/status`, return URL ЮKassa не закреплен на финальной странице оплаты, текущая платежная модель требует миграции базы, а фискальный чек/receipt в запросе создания платежа не передается.

Рекламу запускать пока нельзя. Рекламный трафик нельзя вести на сайт, который может периодически отдавать 500 из-за миграции, а платежный путь еще не закрыт финальной страницей статуса и полной production-проверкой.

## P0: блокеры перед production

1. Код и база данных не синхронизированы.

   При запуске production-сборки главная страница обращается к таблице `consultation_products`. Таблица отсутствует в локальной базе, из-за чего smoke test падает с ошибкой `relation "consultation_products" does not exist`.

   Что сделать: перед выкладкой выполнить утвержденный порядок миграций на production после бэкапа. Минимально проверить наличие миграций 0028, 0029 и 0030, затем повторить smoke test.

2. Нет страницы `/payment/status`.

   В карте маршрутов Next.js страницы `/payment/status` нет. Сейчас `createYooKassaPayment()` берет `YOOKASSA_RETURN_URL`, иначе использует `NEXT_PUBLIC_SITE_URL` или `/contacts`. Для платежей нужна отдельная страница статуса, куда пользователь вернется после ЮKassa.

   Что сделать: создать `/payment/status`, привязать к ней `YOOKASSA_RETURN_URL`, показать понятный статус платежа и ссылку на кабинет/контакты.

3. Запрос создания платежа ЮKassa не содержит `receipt`.

   В продуктах уже есть поля `receiptDescription`, `paymentSubject`, `paymentMode`, `vatCode`, но в `createYooKassaPayment()` они не передаются в тело запроса как чек. Для модерации и эксплуатации нужно явно решить фискализацию: либо ЮKassa/партнер формирует чеки отдельно, либо сайт передает `receipt`.

   Что сделать: подтвердить модель фискализации в кабинете ЮKassa и, если чек должен формироваться сайтом, добавить receipt в создание платежа.

4. Production env и webhook ЮKassa не подтверждены в этом аудите.

   По ограничению задания production env не менялся, реальные платежи и возвраты не выполнялись. Нельзя подтвердить боевые `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`, `YOOKASSA_RETURN_URL` и подписки webhook на стороне кабинета.

   Что сделать: после исправления P0 провести отдельную безопасную production-проверку с тестовым платежом по регламенту ЮKassa.

5. Рабочее дерево слишком грязное для релиза.

   Есть много незакоммиченных изменений и новых файлов, включая `docs/`, `drizzle/0027...0030`, новые API, новые компоненты, а также untracked архивы/дампы в `deploy/`, `backups/`, `rollback-artifacts/`.

   Что сделать: перед релизом разобрать состав изменений, не включать дампы и архивы в коммит/деплой, зафиксировать только нужный код и миграции.

## P1: важно исправить до модерации и рекламы

1. Добавить явную команду для dry-run/проверки миграции продуктов.

   Скрипт `scripts/migrate-consultation-products.ts` есть, но в `package.json` нет отдельной команды. Попытка `npm run migrate:products` завершается ошибкой `Missing script`.

2. Закрепить полный сценарий оплаты.

   Сейчас есть создание платежа, webhook, snapshot продукта, idempotency key, история платежных событий и создание пакета после успешной оплаты. Но полный путь "запись -> ЮKassa -> возврат на сайт -> понятный статус -> кабинет" не закрыт из-за отсутствия `/payment/status`.

3. Проверить пакет консультаций после миграции.

   Webhook создает пакет один раз по `paymentId`, это правильная защита от дублей. Но сценарии использования пакета в кабинете нужно повторно проверить на базе с примененной миграцией.

4. Прогнать smoke test после применения миграций.

   Текущий smoke test не дошел до проверки маршрутов из-за падения главной. После миграции нужно проверить как минимум `/`, `/about`, `/help`, `/reviews`, `/blog`, `/contacts`, `/requisites`, `/certificates`, `/faq`, `/videos`, legal pages, `/robots.txt`, `/sitemap.xml`, `/manifest.webmanifest`, `/login`, `/register`, `/forgot-password`, `/account`.

5. Повторно проверить production-доступность с мобильных сетей.

   Ранее была проблема с TLS/доступностью на Android/Yandex Browser. После DNS/TLS-изменений нужно повторить проверку LTE/Wi-Fi на iPhone и Android.

6. Lighthouse/Core Web Vitals не выполнены в этом аудите.

   Сборка прошла, `next/image` и кеширование изображений настроены, но полноценный Lighthouse-прогон в текущем локальном аудите не выполнялся. Его нужно сделать после стабильного production-деплоя.
