## Ответы по обязательным пунктам

1. Миграция `0030` безопасна для dry-run и подготовки: destructive SQL нет, старые таблицы цен и платежей не меняются. Для production применения нужно отдельное подтверждение.
2. `DROP`, `TRUNCATE`, `DELETE` в миграции нет. Есть только `ON DELETE set null`, это правило внешнего ключа, не удаление данных.
3. `0030` зависит от таблицы `yookassa_payments` из `0028`; локально `0028/0029` не применены. На production это нужно проверить перед запуском.
4. Локально `pricing_items` прочиталась успешно после загрузки `.env`.
5. Найдено 4 старые строки цен.
6. Все 4 строки сопоставлены: одиночные консультации в `single-session`, пакеты в `package-7`.
7. Очные записи не должны сломаться: формат приема остается в записи, продукт описывает цену и количество сессий отдельно.
8. Пакет создается один раз: добавлена связь `user_consultation_packages.payment_id` и уникальный индекс по этому полю.
9. `syncRefund()` использует сумму успешных возвратов из базы и не должен повторно прибавлять текущий возврат.
10. Старые платежи не меняются: новые product snapshot поля nullable, старые суммы не пересчитываются.
11. Production готов только к dry-run, не к миграции.
12. Нужны подтверждения владельца: backup сделан; можно читать production DB; ожидаемое число старых цен подтверждено; можно запускать `npm run db:migrate`.
13. Команды следующего этапа: см. `CONSULTATION_PRODUCTS_PRODUCTION_DRY_RUN.md` и `CONSULTATION_PRODUCTS_ROLLOUT.md`.
14. Запрещено до отдельной команды: production migration, реальные платежи, реальные возвраты, deploy, restart, commit, push, удаление таблиц, изменение старых финансовых данных.
