# Automatic Booking Payment Flow Report

Дата: 2026-07-20

## Что изменено локально

- Публичная форма записи переведена на прямой сценарий: услуга, формат, дата, время, email, оплата.
- Заявка создается только с серверной ценой из `consultation_products`.
- После создания заявки клиент сразу перенаправляется на страницу оплаты ЮKassa.
- Для выбранного слота создается временное удержание через `hold_expires_at`.
- Удержанный слот не показывается другим клиентам, пока оплата ожидается.
- Просроченные удержания освобождают слот.
- После `payment.succeeded` webhook подтверждает запись и ставит `confirmed_at`.
- После оплаты клиенту отправляется одноразовая ссылка `/account/invite?token=...`.
- По одноразовой ссылке клиент сразу задает пароль, входит в кабинет, а оплаченная запись привязывается к пользователю.
- Если оплачен пакет из 2+ консультаций, пакет создается в кабинете после входа по одноразовой ссылке.
- `/account/invite` открыт для гостя и не редиректит на `/login`.

## Поведение оплаты

- `awaiting_payment` означает временно удержанный слот.
- `confirmed` ставится только после подтвержденного webhook `payment.succeeded`.
- `expired` освобождает слот после отмены оплаты или истечения удержания.
- `payment_conflict` используется, если оплата пришла после истечения удержания.
