# Rollout новой модели продуктов консультаций

Дата подготовки: 19 июля 2026.

Это план следующего этапа. Сейчас он не выполнен.

## Предусловия

- Владелец подтвердил: "можно выполнить production dry-run".
- Есть свежий backup PostgreSQL.
- Backup скачан или проверен восстановлением.
- Git-ветка и commit для переноса зафиксированы.
- Production `.env` содержит корректные значения без `localhost` в публичных URL.
- Миграции `0028_yookassa_payment_attempts` и `0029_yookassa_refunds` уже применены.

## Порядок безопасного запуска

1. Проверить production-базу без записи.

```bash
cd /var/www/luneva-platform
npx tsx scripts/migrate-consultation-products.ts
```

2. Сверить число строк `pricing_items` и таблицу сопоставления.
3. Проверить, что `0030_consultation_products.sql` не содержит `DROP`, `TRUNCATE`, `DELETE` и не меняет `pricing_items`.
4. Выполнить сборку на сервере.

```bash
npm run type-check
npm run lint
npm run test
npm run build
```

5. Только после отдельного подтверждения владельца применить миграцию штатным способом проекта.

```bash
npm run db:migrate
```

6. Проверить, что появились ровно два активных продукта:

| Код | Название | Сессий | Цена |
|---|---|---:|---:|
| `single-session` | Очно или онлайн | 1 | 7 000 руб. |
| `package-7` | Пакет 7 сессий | 7 | 42 000 руб. |

7. Проверить public booking и кабинет клиента без реальной оплаты.
8. После этого отдельно принимать решение о включении настоящих ключей ЮKassa.

## Rollback

Если миграция применена, но сайт работает некорректно:

1. Остановить прием онлайн-оплат через env или админку.
2. Откатить код к предыдущему стабильному commit.
3. Не удалять `consultation_products`, если уже есть платежи, связанные с продуктами.
4. Для полного отката базы использовать только проверенный backup.
5. Не править старые платежи вручную.

## Важные ограничения

- Старые строки `pricing_items` не удаляются и не архивируются в миграции.
- Старые платежи не пересчитываются.
- Пакеты создаются только при успешной оплате и привязаны к `yookassa_payments.id`.
- Онлайн-оплата пакета допустима только после финальной проверки условий пакетов, возвратов и списания сессий.
