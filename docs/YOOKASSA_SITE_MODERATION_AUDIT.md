# Проверка сайта перед модерацией ЮKassa

Дата проверки: 19 июля 2026.

Проверка выполнена в режиме аудита: сайт, база данных, production-конфигурация, DNS, платежи, возвраты, commit, push и deploy не изменялись.

## Итоговый статус

**Не готов к отправке на модерацию ЮKassa.**

Главные причины:

1. На сайте нет публичной страницы с полноценными реквизитами исполнителя: не опубликованы ИНН, налоговый/правовой статус и единая ссылка "Реквизиты" или "Контакты и реквизиты".
2. На production не заданы `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY`, поэтому реальная онлайн-оплата через ЮKassa сейчас не может быть создана.
3. Серверная сумма платежа фиксирована: `YOOKASSA_PAYMENT_AMOUNT_RUB=7000`, а на сайте есть пакеты по 42 000 руб. Это создает риск несовпадения цены на сайте и суммы платежа.
4. Правила возврата, отмены и переноса описаны слишком общо; для модерации и реальных оплат нужны конкретные условия.
5. В коде возвратов есть блокирующий дефект синхронизации `refund.succeeded`: после обновления возврата сумма может быть учтена повторно.
6. Production-сборка местами отличается от текущего кода: в исходниках основной email `info@luneva-psy.ru`, а в HTML production и юридических документах встречается `info@luneva-psy.ru`.
7. С текущего ПК проверка публичного HTTPS периодически дает отказ соединения, хотя с самого VPS сайт отвечает. Для ручной проверки ЮKassa сайт должен стабильно открываться у внешнего проверяющего.

## Платёжный сценарий

Текущий сценарий:

1. Клиент выбирает дату/время и формат.
2. Клиент выбирает способ оплаты.
3. Если выбрана онлайн-оплата, сервер пытается создать платеж ЮKassa.
4. При успешном создании клиент получает ссылку на оплату.
5. Webhook сверяет платеж через API ЮKassa и обновляет статус.

Плюсы:

- сумма создается на сервере, а не берется из frontend;
- webhook не доверяет входящему JSON и запрашивает платеж у ЮKassa;
- есть проверка appointmentId, суммы и валюты;
- есть обработка дублей;
- есть история платежных событий.

Минусы:

- ключи на production пустые;
- сумма фиксирована;
- пакеты не связаны с платежной суммой;
- нет receipt;
- нет отдельной страницы статуса оплаты;
- при ошибке создания платежа запись может быть создана без платежной ссылки.

## Безопасность

Положительные факты:

- `/.env` не отдается публично;
- ЮKassa Secret Key используется только на сервере;
- порт приложения `3000` слушает только `127.0.0.1`;
- PostgreSQL слушает только `127.0.0.1`;
- nginx слушает 80/443;
- `server_tokens off` найден в nginx config;
- `www` перенаправляется на основной домен через nginx;
- админские API возвратов находятся в `/api/admin/...` и требуют админскую сессию;
- форма записи содержит honeypot, таймер заполнения и обязательное согласие.

Риски:

- приложение запущено процессом `npm start`, но systemd unit `luneva-platform.service` не найден/неактивен;
- production HTML показывает устаревшие контакты, значит нужно убедиться, что деплой воспроизводим;
- нет подтвержденной фискальной схемы;
- дефект в `syncRefund()` блокирует реальные возвраты.

### 11. Расширяемый каталог продуктов

- Стоимость больше не зависит от формата встречи. Формат (`online`, `in_person`, `discuss_with_psychologist`) выбирается для конкретной консультации и не влияет на цену, сумму оплаты, возврат или остаток пакета.
- Основной источник каталога - таблица `consultation_products`. В коде нет списка публичных тарифов для оплаты: сайт и форма записи читают активные публичные продукты из базы.
- В стартовом каталоге предусмотрены два публичных продукта: `single-session` на 1 консультацию за 7000 руб. и `package-7` на 7 консультаций за 42000 руб. Тестовый пакет на 10 консультаций не публикуется без отдельного решения владельца.
- Каждый платеж ЮKassa хранит снимок продукта: код, название, количество консультаций, цену, валюту, длительность и описание для чека. Поэтому изменение цены в админке не меняет историю старых платежей и возвратов.
- В metadata ЮKassa передаются только технические данные: `appointmentId`, `internalPaymentId`, `productId`, `productCode`, `productName`, `sessionsCount`, `preferredFormat`. Контакт, запрос клиента и чувствительный текст туда не отправляются.
- Возвраты считаются от суммы локального платежа и снимка продукта, а не от текущей цены продукта. Для пакетов юридическая формула частичного возврата должна быть утверждена отдельно.
- В админке добавлен раздел `/admin/products`: можно создать продукт, изменить цену, длительность, число консультаций, бейдж, публичность и активность. Продукты с платежами архивируются, а не удаляются.
- При изменении цены фиксируется событие `product.price_changed` в журнале платежных событий.
- правила полного и частичного возврата;
- возвраты по пакетам консультаций;
- формулировки для персональных данных с учетом психологической тематики.
